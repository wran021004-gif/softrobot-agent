# Case-aware native development campaign, version 2.0.0

This advances the shared-context research loop and the existing eight-variable
builder connections. It does not complete the six-mainline roadmap or launch
the formal fixed/one-shot/feedback comparison. Old stopped campaigns, model
answers, reviews, grants and protected M5 allocations remain historical.

`examples/research_campaign_v2.py` uses one new cumulative project grant from
the 2026-10-07 assignment. Maximums are 28 backend attempts, 24 actual provider
requests, 200 charged workflow operations, 16 standalone numerical operations,
36,000 charged seconds and ten hours elapsed from assignment start. There are
zero additional research roles or workers. Existing configured provider/model,
endpoint, reasoning, token limits, credentials loader and verified TLS remain
unchanged. Failed requests/executions count; unknown usage is not zero-filled.

Before search, twenty final verification slots reserve 19,800 seconds and sixty
receipt operations. Search/reference/repetition work gets at most eight backend
attempts, two per immutable batch. The project-aware downstream guard subtracts
those reserves even when child sessions carry simulation costs. Two requests,
ten operations and 1,200 seconds protect final interpretation/delivery. Existing
900/30/60-second simulation/evaluation/profile ceilings and five-second native
candidate preparation remain fixed. Every planned operation must fit together
with mandatory remaining work. No final slots transfer to search.

Both ordinary and recovered-working-state outgoing requests now use the same
deterministic budget fitter. It measures the complete transport serialization,
including messages, schemas and metadata. The bounded sequence removes duplicate
representations, archives verbose historical reasoning while retaining exact
parameter decisions and hypotheses, then replaces optional archived inventories
with source references. Exact facts, failures, identities, uncertainty, current
permissions, budgets and schemas remain inline. An unfit required request fails
before transmission with an archived section-size report. Bytes, conservative
estimates and provider-reported tokens are separate. No context-cap increase,
paid compression or matched compression-benefit claim is made.

The authoritative campaign allocation supplies current permissions. Original
pilot/recovery restrictions are historical, not current authorization. The
bounded inventory includes incumbent, matching .075/.10 failures, other nominal
successes/counterexamples, both original pilot observations and the exposed
changed-section near-z-plus development failure. Full original sources remain
archived. This is targeted coverage, not an exhaustive repository history claim.
Scientific matching normalizes explicitly zero named initial joints to the
installed initializer's implicit zeros; nonzero mappings and seeds remain
distinct. Raw initializer/builder/dependency bindings still govern strict reuse.
Freshness, scientific novelty, prospective repetition and cache eligibility
remain separate. Known matching points require prospective repetition purpose
when strict reuse is unavailable.

Native `SearchBatchPlan` carries the frozen case ID and seed through validation,
source projection, initializer mapping, candidate construction, execution,
receipt, working ledger and feedback. Only the existing five cases and seeds
17/18 are accepted. A different initializer is not a matched nominal comparison.
All eight granted variables remain available. Structural/control subsets apply
all selected values jointly, rebuild candidate models/workspace/warm states and
execute one stable-v7 closed loop; there is no hidden inner search. Solver
stopping, physical conditions, criteria and inclusive six-sample holding window
stay frozen; experimental v8 and real-time deployment are excluded.

The configured model authors every hypothesis, subset, method, point, allocation
and subsequent decision. Coordinate ask/tell is executable mathematical candidate
generation with absolute joint-acceptance-bucket/normalized-metric guidance;
explicit points are honestly labelled model proposals. Neither proves nonlinear
holding feasibility. Retained evidence reads are available; standalone saved-state
numerical diagnosis is not advertised without its data/adoption prerequisites.
Sealed failed forecasts cannot screen candidates. Applicable mathematics or the
precise capability limitation must accompany the scientific decision.

Selection is frozen before live work as `native_nominal_selection@2.0.0`:
new effective configuration, fresh charged complete nominal joint pass, then
first nondominated candidate in native completed-search reservation order.
This explicitly replaces the fixed baseline's proposal order. Exact source
configuration and full incumbent-relative changes freeze before verification.
Verification uses five cases, two fresh repetitions, incumbent then candidate
per slot. Search/cached receipts never substitute. No eligible candidate means
ten incumbent-only observations to resolve its unknown perturbed performance;
ten candidate slots remain unused. A genuine research STOP ends search; this
characterization and final interpretation are predeclared delivery steps.
Only complete correctly bound matched evidence supports improvement; primary
joint counts and every position/speed component remain separate, with tradeoffs
and incomplete evidence visible. No population reliability or LLM advantage is
inferred from this deterministic development set.
