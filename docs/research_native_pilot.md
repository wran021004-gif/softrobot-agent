# Native first-study pilot, version 1.0.0

`examples/research_model_v1.py` connects the native `research.decide` entry point
to the frozen v1.1 study, exact retained incumbent, effective eight-variable
catalog, shared working-state/request assembly and joint offline acceptance.
This is one new cumulative assignment, not a restart of historical M4/M5 work.
The six-mainline roadmap, formal 28-attempt baseline and three-group study stay
unchanged and unlaunched.

```powershell
& 'C:/Users/gugugaga/miniconda3/envs/softagent/python.exe' examples/research_model_v1.py prepare
& 'C:/Users/gugugaga/miniconda3/envs/softagent/python.exe' examples/research_model_v1.py live
```

Prepare resolves the incumbent's original owner Store from the frozen source
lineage, verifies original configuration/evaluation/profile bindings and copies
immutable evidence. It resolves model settings from the actual frozen study
configuration. Live uses the existing `$HOME/.codex/.env` credential loader;
credentials are never serialized. A sealed implementation fingerprint precedes
the first request. An existing campaign cannot be reset by another output
directory; the fixed grant identity binds one cumulative ledger. A stopped or
failed campaign cannot automatically resume. Engineering fixture grants have
zero model/backend allowances and cannot run live.

The [pilot configuration](../configs/research/native_pilot_v1.json) freezes four
backend attempts total, two per batch, twelve model requests, forty workflow
operations, 16000 charged seconds, two retained diagnostic decisions, zero
standalone numerical operations and zero workers. References, failed attempts
and repetitions consume the same four slots. Normal planning, feedback,
subsequent decisions, configured limited corrections, length recovery and final
interpretation share the same request ceiling. Reservations derive from existing
900/30/60-second execution operations, five-second candidate preparation and
four-request/four-operation/600-second protected delivery capacity. No fixed
runner's three-operation execution estimate is used for native planning.

Nominal seed17 is fixed before outcomes as this pilot's development case. Near-z
and far-y plus/minus cases retain their exact frozen angle/rate mapping but are
deferred for execution. The completed shared-path `near_z_plus` holding-speed
failure is supplied as a subsequent event, with original implementation and
metrics; old preparation records are not rewritten. It is not a matched nominal
reference. The historical nominal incumbent is the source anchor, not a fresh
campaign reference. Four attempts cannot complete the ten-slot matched suite.
No case is chosen after favorable outcomes.

Scheduler capability descriptions and native validation derive from the same
effective catalog/grants used by batch preparation and mutation. Technical
support, study permission and evidence status remain distinct. `control_search`
selects controls only. `structure_search` permits any joint subset containing a
structural variable: each point applies **all** selected structure/control values
and executes one unchanged stable-v7 closed loop. There is no hidden inner search,
extra adaptation allowance or prescribed fixed-baseline structure slot.
Coordinate search numerically generates continuous coordinate proposals;
explicit search evaluates the model-authored sequence and enumerates categorical
material scenarios. Only installed compatible methods are advertised.

`LiveBatchExecution.facts` composes `research.task_acceptance` from the exact
evaluation, profile and sealed motion. Ask/tell feedback, bound comparisons,
model-visible outcomes and final delivery share that result. Terminal reach
alone never means joint success; maximum holding speed and inclusive coverage
remain required. Accepted, valid failure, missing, incomplete and invalid states
remain distinct. Computation and deadline misses are separate offline diagnostics.
Historical results retain original labels; derived offline acceptance is a new
view, not a rewrite of sealed historical evaluations.

The actual outgoing native payload passes through `assemble_working_request`.
Immutable working checkpoints use a separate archive-only Store and the exact
source manifest; the execution Store remains the budget authority. Working state
retains facts, claims, candidate/task/structure/implementation identities,
chronology, original references, budgets, experiments and STOP. The same canonical
facts generate the final report view. Retained prediction/plans/motion reads are
distinct from new calculations. Sealed M5 negative findings convey no screening
authority or v8 adoption. The model authors the live hypothesis, values, method
and all subsequent choices, including voluntary early STOP.

Focused validation: `python -m unittest tests.test_research_model_v1
tests.test_research_tasks -v` passed nine checks. Native engineering fixtures
exercise actual schemas, aliases, decoding and `Host.invoke(research.decide)`;
they make zero provider/backend calls. Both joint methods preserve frozen
conditions, and the next actual payload retains the authoritative reach-pass /
holding-fail outcome. These checks do not repeat the completed simulation smoke.
