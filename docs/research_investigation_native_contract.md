# 调查原生工具契约与历史交接

新活动在模型配置 `parameters.investigation_contract=business_fields_v2` 下使用 `tools/investigation_contract.py` 的单一 Pydantic 契约：`evidence_read` 与 `investigation_return` 都直接接收业务字段。发送 schema、严格 JSON 解析和公共请求构造均由该契约提供。外层 `arguments/reason/tool_version`、未知字段和错误标量类型被拒绝；公共工具元数据由程序构造。未声明此版本的历史活动保留原读取封装与报告格式，不把旧无效响应追认为成功。

`research.investigation_handoff@1.0.0` 只接受活动授权预先声明的历史绑定，核对停止状态、项目/运行/节点/数据库身份、原报告和验证记录。复用记录存于 `historical_investigations`，与本轮真实调查节点分开；不改写旧状态、不执行调查者、不释放旧费用或预留。主模型仍须通过公共读取与正式处置入口形成新记录。

新授权活动见 `tools.research_v1_resume`：`prepare` 冻结新身份、原始授权、代码、配置、历史状态和独立阶段额度；`execute --mode reuse` 仅复用报告执行新主模型；通过独立语义审查后才允许协调阶段，再通过后才允许固定案例。每阶段只能启动一次，零自动传输重试，所有提交节点必须收尾。新预算为主模型复验 8/128/2400、协调 32/512/8000、固定案例 0/14/6000（模型/工具/账本秒）。每节点最多 8 次模型、12 次证据、900 秒，最大并发 2。协议纠正按阶段和角色保护额度，单节点最多 2 次；总上限 6。

针对性回归覆盖新旧读取/报告参数、保存的旧错误响应、错误包装、未知字段、精确数值/类型/身份与可见性、容量保护、付费纠正计数、历史交接身份及旧数据库不变。离线 fixture 不代表真实模型验收。
