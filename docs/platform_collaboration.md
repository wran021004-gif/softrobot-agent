# 记忆、技能与运行时协作

## 记忆

工作记忆在会话状态中记录最新回执、已读取内容身份和分页位置。跨运行记忆在同一项目数据库索引，支持任务族、任务版本、后端、模型、失败类别和标签筛选；每次检索重新检查来源内容摘要，过期／失效／缺失来源不进入结果。

`model_note`、`direct_observation`、`verified_record`、`hypothesis` 分开存储。摘要只是一段数据；科学有效性由其引用的评价结果决定。verified_record 必须由可信本地宿主检查评价来源，模型不能在参数中自行提升结论级别。

`memory.save / memory.search` 是公共工具。下一轮上下文自动包含兼容记录的短摘要与来源；`context_delivery` 保存实际提交载荷，可以核对检索与投递。仅检索得到不等于已经提交给模型。

## 技能

复用 `skills/registry.py` 和 `tools/skill_policy.py` 的 candidate → validated → approved／deprecated 生命周期、不可变版本、追加验证与来源检查。原系统默认行为不变；平台通过可注入的证据读取器映射新项目证据，没有另一套审批状态机。

平台开发库在项目 `development_skills/`；仅当策略显式允许时候选／验证技能可进入开发上下文。公共工具接通 `skills.search / skills.propose / skills.validate`，没有伪造人工审批的公开工具。开发验证记录只能证明证据所述的接口经验，不是人工正式批准。

当前技能类别是指导策略及工具组合，后续执行仍经过公共工具入口。任意可执行代码技能尚未接入；如未来需要，必须作为受信任实现包登记自己的契约、能力和资源，不从技能文字执行代码。

跨运行经验的验收：保存参考信号 → 提案技能 → 保存带策略摘要的确定性验证证据 → 登记验证 → 后续同类会话检索 → 在模型实际输入中找到技能及来源。失败和过时版本不会被删除或改成成功。

## 协作任务单

`WorkOrder` 包含工作身份、目标、具体工作者绑定、固定输入内容、基础候选、允许工具、资源额度、超时、依赖、输出契约、独立写入范围与完成检查。见 [worker.order.yaml](templates/platform/worker.order.yaml)。输入中的 artifact_id 必须替换为本项目已经保存的真实证据身份。

运行时流程：

1. 通过 `workers.submit` 公共工具进入协调者；核对父会话权限、输入、工作者版本、工具子集和输出契约。
2. 同一项目 SQLite 原子预留工作者的一次固定证据读取、工作者调用和超时额度，检查排他资源容量。
3. 启动真实本地 Python 进程；输入复制到该工作者目录，校验摘要；实现只能通过其契约得到固定输入并写自己的输出。
4. 只读 `workers.status` 查看状态。`Coordinator.collect` 显式收集，核对输出类型、身份、源信号、采样索引和数值；提交不可变输出并结算资源。
5. `workers.accept` 将当前基础候选、结论键与已有结果比较；过期结果标 stale，矛盾标 conflict，完整相容结果才接受。同一 work_id 不重复合并。

参考工作者只进行固定证据读取和确定性信号查询；其预算是一条原子预留，不再叠加第二套工具计费。更复杂工作者需要显式接入受限工具客户端，不能从这个参考实现推断任意代码已经隔离。

MATLAB 等共享资源必须登记排他容量；不会默认线程安全。取消和超时处理当前宿主持有句柄的本地进程；宿主重启后的未知句柄不能按 PID 猜测并终止其他进程。

两个参考工作者分别查绳索与接触计数，真实工作时间必须重叠并保留时间戳。该验收证明本地调度及验收接口，不证明两个真实语言模型已能良好协作，也不证明自然语言因果判断正确。
