## 第六轮故障依据

以 `runs/round6_ready` 的实际记录为准：7 次真实模型请求、6 次工具执行、2 个候选、2 次真实仿真。旧交付文档的“等待密钥”是当时快照，不能代表随后实际运行的状态。

七次实际发送请求依次为 **11,574 / 14,307 / 24,425 / 42,188 / 44,857 / 48,477 / 50,963 字节**。通过该运行保存的源码快照重建待发送第八次请求，大小为 **61,351 字节**，触发本地 60,000 字节上限；第八次未发送，没有第八次模型扣费记录。主要原因是 `compact_result` 原样携带 data，读取的完整 `mujoco_result.json` 约 16 KB 被持续回放，当前 context 又重复携带完整评价和决策。

决策 3 创建候选被拒绝：模型确实引用 c000 的 `execution/.../mujoco_result.json`，但程序只接受 `attempts/001_evaluate_candidate/result.json` 的精确字符串。决策 4 换为包装路径后才通过，多消耗一次模型请求与决策。
