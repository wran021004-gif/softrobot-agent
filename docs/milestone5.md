# Milestone 5 initial prospective pilot, 2026-10-04

The first bounded pilot **completed with an inconclusive result**. It demonstrated neither full-task speed-direction prediction nor candidate-order prediction. Milestone 5 remains open; no automatic screening, general reliability, structural screening or controller-family comparison was validated. See [delivery.json](../evidence/milestone45_continuation_20261004/delivery.json) and the [frozen forecast](../evidence/milestone45_continuation_20261004/single_context/pilot_forecast_seal.json).

The pilot reused the existing `TrajectoryWorkspace`, independently checked local plans and `diagnostic_math.NonlinearModel` rollouts, with a small candidate-bound receipt tool. Reference was the evaluated new structure `bebcfd47274940fb88a55ce5a2457c4c`: near/far 0.16/0.11 m, compliant scenario, section scale 0.95, weights 0/0.05. The already accepted immutable adaptation batch contained holding weights 0.05 and 0.10; terminal weight and structure remained fixed. Forecasts did not filter candidates, reorder execution, change acceptance or change physical comparison policy.

The [protocol](../evidence/milestone45_continuation_20261004/single_context/pilot_protocol.json) freezes the saved controller-observation state at 0.34 s, previous applied input from update 33, candidate configurations and scientific identities, coordinate mapping in the sealed `control_spec.json`, tendon order, units, one-period effective controller horizon, bounds and numerical limits. State coordinates are projected GVS curvature/rate coordinates; physical quantities are world-frame metres and metres/second, and tensions are newtons. Input ordering is near_t0, near_t1, near_t2, far_t0, far_t1, far_t2. All local attempts use a common cold constant previous-input seed with independently regenerated model states, instead of reconstructing a historical warm plan. Each candidate gets its own weight-specific controller attempt. The rollout holds that attempt's selected first command for 0.01 s with 0.002 s implicit Euler steps in `model.gvs@1.0.0`.

All three independently feasible local attempts stopped at `verified_settled_seed`, selected iteration zero and returned identical first commands. Equality was an observed result of the controller policy, not an imposed shared control sequence. Their local endpoint speed was 0.010623547 m/s, local endpoint target error 0.000816416 m and drift 0.000076669 m. Relative to the common initial state, speed increased by 0.008542930 m/s in every local rollout. These quantities describe this saved-state interval only; they are not the complete task's maximum holding speed/error. Different weighted objectives were not used to rank candidates.

The research model froze an explicit abstention before either backend outcome: both holding-speed directions unresolved, both holding-position directions unresolved, no ordering prediction, joint acceptance unknown. The 0.10 point loses joint acceptance, despite improving terminal error. Position/speed vectors and the existing acceptance-first comparison policy determine these classifications.
