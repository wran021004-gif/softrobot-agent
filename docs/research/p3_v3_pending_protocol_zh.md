# P3 待批准设计与比较协议

两份配置 `study_p3a_v3_pending.json` 和 `study_p3b_v3_pending.json` 仅冻结 V3 家族、原任务、现有方法能力、空证据池和待批准标记。计数预算全为零，原有 `PENDING_EXPLICIT_APPROVAL:` 门禁仍生效；启动前必须取得单独的 P3 授权、决定预算、更新配置并重新冻结，不能把模板当作已获执行许可。P3-A 使用 `positive_high`；P3-B 使用 BF7 三个原冻结条件，每个条件可单独优化控制，但同一物理结构三个条件都经独立完整回放通过才是共同验收。原 BF7 V2 成功证据不能证明 V3 成功。

P2 的一次 T1 有 26 次回调、15,600 步和约 3.23 s 的总记账，不能从一个样本推断高分位耗时或结构更复杂时的费用。可供审批前评估的试点建议：P3-A 最多 10 个数学条目、每次 T1 最多 51 回调、最多 1 次独立回放、数值预算 300 s；P3-B 可先试最多 12 个数学条目、最多 3 次独立回放、数值预算 300 s（每个完整三条件结构至少消耗三个 T1 条目）。Provider 含 Reporter 的上限暂以 8 次作为讨论用上界，必须先根据 P2-B 真实请求、token、上下文尺寸和恢复情况复核；当前没有实际数据支持其充分性。各数字仅为建议，全部未写成激活预算。

在相同 V3 合法域、相同冻结任务、相同网格与评价口径下设置三组，预先冻结各组相同的数值、物理、分析及总成本上限，并同时记录 Provider/token 和所有失败费用：

- A 固定结构加控制：在正式启动前公开确定一个 V3 域内的普通中性两段六腱基准，建立本组来源合法的结构证据并冻结 `fixed_structure_reference`，只允许控制优化和验证。当前模板没有假装已拥有此引用；该引用必须在授权后的本组 Store 中合法建立，且应禁止其他结构变化。
- B 固定策略结构—控制：从相同公开基准出发，预登记对 `segments.0.length_m`、`segments.1.length_m` 的总长保持方向 `[+1, -1]`，固定方向、步长、顺序与停止规则，步长及合法边界在授权前由能力视图校验并固定。每个候选分别绑定、重新优化控制；不让 Agent 据反馈变更参数块或顺序。使用 V3 `adaptive_joint_block_v1` 的具体路径与投影能力，但先核实其内部自适应更新不会违反固定策略；如不满足，使用预登记的确定性候选生成序列和原有 T1 接口，不声称现有方法已经提供该对照。
- C Agent 选择：从相同 V3 域及预算出发，允许 Agent 根据本组真实证据选择起点、诊断、参数块与停止；不要求预定首动作。P3-A/B 模板是 C 组起点，而不是 A/B 已完成的独立组配置。

比较每组按实际总费用达到的最佳完整 J、原始任务指标、独立回放接受率、未完成比例、总积分步数、数学条目、Provider 请求及 token、墙钟与 Store 数值秒；相同随机规则下重复次数和预期统计精度需另行批准。仅对同一任务、同一物理条件、相同控制适配及可比计算额度的完整结果做普通排序，未完成计算单列，不填入低分。有限预算结果不等于理论最优或证明结构必要。

当前准备缺口：A 组结构引用和 B 组确定性执行配置尚未冻结；Provider 授权与真实 Agent 表现、独立回放、真实 T2 敏感性及跨条件实证均未完成。模板不能通过复制旧 BF7 证据来填充这些缺口。

P2-B 实际新增成本证据：4 次请求消耗 190,260 tokens，其中第四次在 32,768 输出 tokens 时截断，输入大小增长到 196,007 bytes；仅凭“8 次”不能判断 P3 Provider 预算是否充分。恢复机制、上下文和模型输出上限必须先经真实验证，之后再拟定可审批的 P3 Provider/token 预算。当前 P3 模板仍为零激活预算。
