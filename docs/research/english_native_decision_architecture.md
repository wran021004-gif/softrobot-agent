# English-native research decision architecture

The integration base is `91573147e7a2bdf0044cf9621fbf4929568d9377` on `codex/agent-guided-codesign`. The opt-in `english_decision_v1` Study contract uses the existing Store, Strands session, evidence admission and evaluator. Historical Studies keep their frozen behavior. No live Provider request, scientific worker, physical rollout, NMPC or training was used to validate this implementation.

## Ownership and roles

`config.py` freezes the versioned role and handoff policies. `agent.py` owns actual Strands tool definitions, request construction and accounted transport. `research_context.py` projects Store facts into `research_decision_brief_v3`; `reporter.py` composes read-only reports and validates sources. `core.py`, `evidence_policy.py`, `evidence_views.py` and the registered evaluator retain evidence identity, formal reads, admission and task acceptance. `provider_context.py` estimates serialized input tokens and preserves the hard guard; `session_handoff.py` owns verified SDK snapshot rotation. `experience.py` retains optional procedural guidance and grants no scientific authority.

New Studies opt in inside `research_decisions`:

```json
"architecture": "english_decision_v1",
"role_policy": {
  "version": "research_roles_v1",
  "main": {"thinking": "disabled", "reasoning_effort": "none", "max_tokens": 4096},
  "reporter": {"thinking": "enabled", "reasoning_effort": "low", "max_tokens": 2048}
},
"handoff_policy": {"version": "token_handoff_v1", "input_tokens": 38000}
```

The handoff policy defaults to the shown threshold for the opt-in architecture; the resolver verifies it fits beside output and framing reserves. Both roles share the frozen model, endpoint and accounted Store ledger. Reporter receives its own output cap. DeepSeek documents the profile values at [the Chat Completions reference](https://api-docs.deepseek.com/api/create-chat-completion/).

## Evidence, decisions and recovery

New instructions, tool guidance and Reporter prompts request English at source. The opt-in path excludes automatic history, mathematics, control seed, background and supplied-evidence imports. An exact read of an incompatible textual Store artifact returns an English unavailable indication and source pointer without changing the artifact or granting a formal read. Common non-English scripts are detected without rejecting SI symbols or mathematical notation; this narrow check is not a general language classifier and does not prove that Latin-script text is English. A noncompliant Main response stays in its original accounted transport receipt and blocks consumption; a noncompliant or uncited Reporter interpretation is unavailable, with original response bytes retained. No translation or evidence rewriting is performed.

The L0 brief shows task and candidate state, sourced metrics and model quantities, a bounded excerpt of the latest Reporter interpretation, current action directions and budget, and evidence/closeout navigation. An action menu entry is a request-level eligibility indication; actual parameter, source, model, identity, Study authorization and resource checks remain authoritative at dispatch. SELECT needs the Main Agent to receive a complete fresh passing independent evaluation through `evidence_read`; Reporter reads and partial/withheld reads do not count. Multi-condition SELECT retains the original all-conditions and same-structure checks. STOP retains the exact registered result citations and existing gate.

In the ordinary decision request, `research_analysis` and its full method union are absent. Direct legal `research_plan` actions remain available. A settled diagnose decision naming an owned candidate and registered authorized method exposes that method's pruned `AnalysisRequest` schema on the next request; the original dispatcher remains the execution authority. The selected candidate and frozen protocol are bound in that schema. This path costs one additional Main tool round before a mathematical execution; simple Plan actions need no such round. Existing exact-wire replay restores the originally saved tool definitions.

Reporter priority retains deterministic feedback for ordinary/repeated cases and selects Low for new incomplete or changed complete results, a detected model/physical constraint mismatch, or explicit investigation. It requests approximately 200–400 words for substantive explanations. It cannot change facts, admit actions, or grant read credit. Full reports stay retrievable.

When existing live handoff admission is enabled, the projected complete SDK request, including current L0 and tool definitions, is tokenized using the pinned offline tokenizer. Threshold rotation uses the existing verified completed-invocation or paired-feedback boundary. The new session is rebuilt from the Store and carries pending feedback when required; no old reasoning transcript is replayed. Unknown sends, unmatched feedback, unsettled receipts and active workers still block rotation. Output reserve and framing headroom remain separate from the soft input threshold. No provider token count or billing is inferred from this estimate.
