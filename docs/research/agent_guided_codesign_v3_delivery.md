## Implementation

- `da9882e`: `serial_family_space_v3` and `serial_family_generation_v3`, with a registered `candidate.family@7.0.0` builder. Each compact route starts at the fixed base, traverses every intervening segment, and anchors on the specified segment. Per-segment radius, angle and guide station are explicit. V3 checks conservative section-envelope and pairwise straight-chord clearance, physical guide-hole size and existing compilation constraints. The supported geometric subset has coaxial, unrotated serial interfaces; arbitrary route overrides are rejected. This is an ideal frictionless tendon model, not a fabrication-process, friction, wear, cable elasticity or swept self-collision simulation. V1/V2 meaning and old route evidence remain unchanged.
- `b3fbe6e`: `research_analysis` exposes `tendon_force_capability_v1` for a V3 candidate at its frozen native initial state. It reuses `geometry().Jlength`, checks the native coordinate and tendon order, obtains the actual compiled MuJoCo ideal-tension actuator bounds, and computes the exact linear box support of `-Jlength.T T` along an Agent-supplied generalized direction. It is an instantaneous diagnostic, not Cartesian tip force, global reachability or dynamic feasibility. Cartesian-direction conversion and arbitrary saved-state support are not implemented.
- `7102c83`: `adaptive_joint_block_v1` accepts an owned V3 seed, concrete effective parameter paths, optional normalized direction coefficients and per-path bounds. A deterministic normalized pattern step uses a box-constrained projection for fixed or interval total length. Every proposal goes through the V3 generator and original candidate/analysis infrastructure; each Native condition gets its own bound control initialization and T1 optimization request. Finite comparable improvement expands the radius, a finite non-improvement shrinks it, and an incomplete result leaves it unchanged. This is observed-score pattern search, not a prediction-ratio trust-region certificate. Existing `normalized_joint_block_v1` and coordinate methods retain their semantics; a V3 previous-candidate refinement uses the new method.
- `a690255`: optional V3 `registered_applicable_v1` method scope freezes the registered method set without forcing an initial route; capability, exact model applicability, mathematical entries, Native limits and formal authorization still apply. Explicit legacy method grants remain unchanged. The zero-budget [search example](../../configs/research/study_serial_v3_search_example.json) provides discovery only and is not authorization to run a Study. V3 L0 gives four action categories and a compact structure-action index; the existing `evidence_read` working-set view returns details on demand. Search feedback exposes dimensionless J, actual cost and incomplete states; STOP can declare a reason, with a scoped exclusion requiring registered verified evidence.

V3 parameter capabilities expose effective concrete segment and tendon-path parameters with units, bounds and physical components. The existing `nonlinear_response_v2` direction contract can represent a simultaneous segment-length and tendon-radius direction when the Study grants those paths. This is an interface check, not a new T2 sensitivity result or a KKT certificate.

## Verification and cost

Focused offline fixtures checked V3 single-, two- and three-segment compilation, proximal and distal anchors, different per-segment radii and angles, route order, illegal mid-chain override, illegal clearance, V2 historical distal-start behavior, candidate and builder binding, and MuJoCo XML loading and actuator order. One test compared the analytic `Jlength` with MuJoCo's tendon Jacobian at the same V3 state and channel order, and checked box support against the actual actuator bounds. `mj_forward` was used for this geometry comparison; no integration or independent physical evaluation was performed.

The force-support test used four separate ephemeral fixture worker executions during development, each with one mathematical entry, one model build and zero physics steps or independent replays. The final focused run recorded 1.0606912 numerical seconds with the worker started; the other three fixture durations were not retained. These are engineering fixtures, not Study evidence. No real Provider request was made.

Synthetic T1 responses exercised V3 search through the real candidate generation, candidate-bound control initialization, request construction, accounting/checkpoint paths and receipt recovery. They tested simultaneous segment-length and per-segment tendon radius/angle changes, fixed-total and interval projection, radius expansion/shrinkage, and incomplete/no-J handling. They do not prove a real Native control optimization converges or that a task passes. Existing Native per-structure optimization is reused without changing its numerical algorithm.

Focused P0 tests covered the versioned method scope, legacy strategy gate, recoverable on-demand method details, STOP certificate gate, unavailable/incomplete status and actual Native-cost projections. The selected request-boundary Handoff simulation tests passed. Three older C1 context tests and one old mixed-search configuration-digest assertion also fail on the unchanged `integration/research-next` worktree in the same environment; they were not changed or represented as regressions fixed here.

## Readiness and limits

Within the declared V3 model and topology subdomain, the interfaces now permit an Agent to generate a candidate without a historical successful design, request a scoped force diagnostic, select a concrete parameter block, produce coupled legal proposals and invoke the existing finite-budget control reoptimization route. Their individual bindings and recovery are verified by the fixtures above. This is interface readiness only: an actual new-task model decision sequence, real V3 Native control optimization, and independent original-task acceptance have not been performed. Consequently there is no evidence here that an Agent will select a useful hypothesis, or that any V3 design is feasible for a particular task.
