## Responsibilities and versioning

- `contracts.py`: additive diagnose `next_research_action` and ScientificQuestion
  v3 parameter_group/parameter_id. Old Plan serialization omits the absent field.
- `scientific_intent.py`: existing deterministic adapter owns explicit interface
  choices, candidate-specific parameter projections, semantic feedback, and
  compilation to original AnalysisRequest. It creates no candidates or workers.
  parameter_capabilities -> family_analysis_parameters remains the sole domain,
  effectiveness, method and authorization authority.
- `agent.py`: loads the completed Plan's explicit choice unless a later explicit
  research_route supersedes it. A v3 diagnose without a choice leaves neutral
  discovery. Direct evidence reads preserve the choice. Only submitted scientific
  requests reach original admission. The scientific compiler validates operation
  semantics before parameter membership, including at the actual tool boundary.
- `core.py`: version/admissibility checks for the additive choice, and accurate
  diagnose execution_entry from the resolved Study interface. Original Plan,
  evidence, cost, task and Worker admission remain authoritative.
- `research_context.py` / `task_constraints.py`: minimal C1/L0 action distinctions
  and matching loaded-tool handoff. Current-structure Native T1, unchanged-input
  effects, saved-T1 T2 aggregation, and new structure/control search stay distinct.
- `config.py` / `evidence_policy.py`: explicit new-Study opt-in and candidate-bound
  scientific diagnosis admission; no mutable configuration reload for old Studies.
- `tests/research/test_p63g3_action_handoff.py`: G2 saved inputs, grouped registry
  choices, semantic priority, neutral discovery, actual SDK/Mock wire, original
  search admission and saved-T1-only T2 checks. Scripted model replies and synthetic
  T1 results are test fixtures, not scientific evidence.
- `tests/research/p63g3_prepare.py`: single-use Operator preparation using original
  candidate generation, baseline, Native T1, independent replay and Reporter.
- `tests/research/p63g3_audit.py`: SQLite mode=ro/query_only audit of the new Store,
  exact Provider wire, feedback, costs, worker boundaries, and closure. No requests.

Only new Studies frozen with analysis_interface=scientific_question_v3 use explicit
diagnose continuation and grouped physical selection. V1/V2 contracts and their
legacy continuation remain compatible. Their mixed-operation feedback is repaired
without changing any numerical semantics or historical records. Scientific mismatch
returns needs_choice, scientific_execution_started=false and no new result; it
does not silently convert T2 into search. New structure/control requests still
compile to the original FamilyMixedSearch and original Native settings, including
four uniform knots and independent 80-iteration/120-callback limits.
