## Knowledge 为什么没有读取

原 Study 的 73 次 Provider 请求中，70 次 Main 请求均含两条 revision 2 Knowledge 的摘要、精确 `read_query` 和 `experience_retrieve` Schema；另外 3 次是 Reporter 请求。69 次 Main 请求有成功响应，一次响应丢失，不能确认送达。实际检索、读取、声明采纳均为零。

冻结目录可用，原白名单含两个条目的 revision 1/2 元数据。使用原 Schema、原过滤条件，在独立工程 Store 中检索得到两条 revision 2，并成功读取，正文哈希与原文件相同。未发现这两条卡片受到路由、过滤或上下文投影阻断。

能够确定的直接原因是：保存及执行的 Main 工具调用没有请求检索或读取。为什么没有选择调用，证据不足。不能归因于“没提醒可读”、理解能力不足或故意忽略。原提示通用、没有明确关联决策阶段，这是可改进之处，不是已证实的心理原因。

另外修复了读取送达统计中完整引用与 Main 短引用不一致的问题；它可能把未来已读正文错误标成未送达，不能解释原来零调用。

## 简洁的 Experience / Skill

原 33 条 Knowledge 元数据及正文全部保留；原 Study 白名单不变。新配置增加六条条件式 Skill、三条抽象 Experience。Skill 约 130–162 英文词，Experience 约 185–212 词，含各自 JSON 字段；没有成功结构参数、控制序列或任务答案，也不增加决策归属字段。

原 `research-bounded-continuation@2` 帮助区分有限搜索失败与不可行；`research-witness-and-cost@2` 帮助区分数学观察、独立验收和真实成本。它们没有当前执行器的输入覆盖语义，也不能直接给出候选专属实验。

新增 Skill 覆盖有限搜索、参数模型、同工况比较、从局部结果设计实验、继续或 STOP、独立验收。Experience 只保留“观察→假设→行动→结果→修正”的短轨迹，成功与未完成均有明确限制。历史任务值不能转移为当前证据。

仍使用同一个可选 `experience_retrieve`，新增可选 `knowledge_type` 过滤。首次 Plan、同候选至少两次有限控制搜索未通过、选择 STOP 后提交解释前，按白名单与触发条件给出最多一至两条摘要和精确读取入口。首次主要提示 Skill；后两阶段可各选一条 Skill / Experience。摘要最长 200 字符，不预载正文；同节点确认送达后不重复。

记录分别对应：成功响应中的提示送达、真实读取收据、Plan 声明的采纳绑定。决策影响需要实验选择与解释中的可观察证据，不能由前两者自动推出。STOP 继续使用原 Plan 的解释字段和原准入，没有新循环或强制读卡门禁。

## 当前执行模型的参数作用

扩展原数学能力目录的 `execution_semantics`，由现有 compiler / MJCF force law 支持；分析结果补充实际 `input_binding`。没有新增物理推理器或改变动力学公式。

- 理想张力模式的显式绝对张力输入覆盖默认预张力；同一状态、同一完整绝对输入下，单改默认预张力不改变该运动。重新初始化控制属于不同实验。
- 当前 MJCF 的腱直径用于显示和间隙合法性，没有腱弹性、质量或摩擦项，不能解释成腱弹性刚度。其他执行器模式单独说明，不能把 Native 理想张力结论泛化为所有模型禁令。
- 目录同时说明几何、质量、骨架刚度、阻尼、驱动映射、输入界限和合法性作用；可识别性仍由原数学准入决定，描述字段不授予计算权限。

两条真实错误来自先前工程决策对照，已保存原请求片段与源文件哈希作为回归，不冒充原正式 Study 执行过的科学实验。回归在相同状态/输入下检查真实 MuJoCo 模型的力、质量、刚度和加速度不变，禁止积分调用。

## 真实 Provider 对照

使用原模型 `gpt-5.6-sol` 和原历史上下文，独立工程 Store 最多允许 21 次调用，实际 14 次。两组各七臂：原 none；加入适时提示与确定性语义的 none；相同输入的 medium；固定 none 下不新增 Knowledge / 仅 Skill / 仅 Experience / 二者兼有。每组内任务、工具授权、候选、证据和预算一致；none / medium 请求除 reasoning 配置外相同。原历史本来已有提示，因此“不新增 Knowledge”不是从未见过 Knowledge。

第一组取历史第 73 次请求，路由已经选择 STOP，七臂全部 STOP。这有明确入口偏差，保留结果及费用。第二组有界纠偏，取第 70 次请求，允许 diagnose / analysis，七臂全部选择继续诊断。不是统计样本扩增，也不将选择继续本身计为能力提升。

Gateway 契约和真实 HTTP 200 响应均支持 medium，实际 reasoning tokens 共 629。正式配置仍为原 none，未改原模型身份。

## Native 批量搜索已准备的正式范围

新 Study 配置 `m1-elevated-native-search-20261102-campaign1` 开放可选 `research_plan(search)`，与 generate / research_analysis / physical_replay 并存。原恢复机制拒绝改变冻结 specification，因此不能在旧 Study 上加 search；采用独立 Study，并只分配原余额：Provider 87、公共操作 569、数学 78、Replay 18。旧成本、STOP 与授权保持原样，不补回额度。

Main 可选合法参数组任意子集：段数、腱数、跨段策略、段长、材料、截面、腱路；支持 1–9 段、1–7 腱。可固定拓扑、指定连续区间、选择起点、使用可表达的合法旧候选作结构起点，并自主减少 proposal、条件分析和控制优化力度。可变段数 / 腱数 / 跨段策略要求明确起点，避免把列表第一项误当科学最优。连续参数未指定的起点仍使用 FamilySpace 默认值，不代表最优。

原 `bounded_mixed_coordinate_v1` 从起点沿已选坐标作有界局部移动，使用原 FamilySpace 生成、合法性检查与 Store。不能保证全域覆盖；proposal 少时更不能覆盖每个所选坐标。旧候选的可表示腱路被保留；无法无损表示的任意腱路、截面或额外物理参数明确拒绝近邻种子，转用 generate。没有新优化器、账本或 Planner Agent。

只启用 `mujoco_control`：每个合法结构分别生成三个冻结条件的候选身份和新控制初始化，重新进行 Native 控制搜索。保留 Elevated M1 v2、任务约束、12 cells/segment、原 backend 1.1.0、接触与执行器配置。最多 8 proposal / 24 工况分析；单工况最多 800 回调 / 100 迭代 / 4 knots。剩余资源不足以覆盖三个条件时准入拒绝，不启动残缺的正式联合搜索。

返回每结构参数、来源、三个条件的有限预算最佳结果、违反量、迭代 / 回调 / 停止原因 / 成本、失败与未完成项、可比候选和覆盖限制。共同请求控制设置下仍需核对实际力度；同时改变多项结构不能归因于腱数。原评分按任务违反量排序，没有用少腱惩罚抵消失败，也没有强制探索腱数顺序。

搜索结果只产生有限预算数学证据；不继承旧结构通过状态，不自动 Replay / SELECT。通过仍须原三条件独立验收和联合 SELECT，即时成功关闭规则保留。
