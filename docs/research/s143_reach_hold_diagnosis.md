## 5. 控制问题、IPOPT 与竞争机制

实际控制是 0.1 s 上限的滚动窗口：horizon=10、substeps=1；从 0.26 s 起缩短至真实 0.35 s deadline，
最后仅一个区间。初始问题 340 个变量/240 个动力学等式，最后为 61/24。
目标包含位置、曲率率、张力和张力变化的软惩罚；位置尺度 0.01 m、末端速度尺度 0.02 m/s。
tracking/terminal position 权重为 1/5，曲率率 stage/terminal 为 `1e-4/1e-4`，
tension/variation 为 `1e-4/1e-3`，两个末端速度权重均为 0.1。
约束为实测初态、隐式动力学和 0–8 N 输入边界；**没有保持速度或保持位置的硬约束，也没有终端平衡约束**。

速度惩罚确实进入对应时刻，但其含义不能只看“权重 0.1”：

- 冻结实际模式是 `time_integral_v1`，不是 Agent 后来声称的 window-normalized。
  每个保持节点的系数是 `0.01×0.1=0.001`，终端速度系数为 0.1，后者为单节点前者的 100 倍。
  0.29 s 更新的六个保持节点若速度均恰为限值，离散 stage 总成本为 0.006，终端成本为 0.1；均为软权衡。
- 绝对时间 holding mask 在 0.30 s 起生效、brake lead=0；0.20 s 更新第一次在窗口内看到 0.30 s。
  0.29–0.34 s 的所有下一节点均受 holding cost 影响。已固定的当前状态不受未来控制改变。
- 原 0.30 s snapshot 中，增刚 selected holding cost=0.0005803、terminal speed cost=0.00000767，
  terminal curvature-rate cost=0.0061925；速度项实际非零，不能称“没被优化”。
  0.34 s 两方案预测下一速度分别 0.024217、0.028244 m/s，也说明惩罚并不保证每点达标。

IPOPT 使用 max_iter=120、tol/acceptable_tol=`1e-6`、limited-memory Hessian、exact AD reverse Jacobian，
无 CPU/wall 提前停止；warm start 会移位上一计划并从当前实测投影状态重积分所有猜测状态，
不是每次从零开始。但没有传入 `lam_x0/lam_g0`，即没有对偶 warm start；deadline 缩窗还会重建不同维度的问题。

“可用”来自独立可行性筛选/已有恢复，不等于最优。所有已接受计划均比本更新初始化目标更低；
这是有用的可行、经验性改进证据，**没有局部最优误差界**。
例如增刚 0.30 s：初始化目标 0.0160299，49 次迭代选中 0.0103808，违反 `5.86e-7`；
120 次返回反而为 0.324015、违反 `6.13e-6`。最后迭代可行也不代表更优。
原快照保留 objective/feasibility trace，却没有 IPOPT 的 inf_du、完整 KKT/complementarity 和相应乘子；
不能用小 primal residual 声称 stationarity，更不能量化“距离有效局部最优还差百分之几”。
各更新的目标还随实测初态/窗口维度改变，不能把 0.29→0.34 s 的目标上升直接当同一 NLP 的优化退化曲线。

**明确的求解不足证据**是反复触及迭代数上限、raw 动力学违反和同次迭代后段退化；
函数评价约 286–636 次/更新，工作被实际用于非线性求解。有限迭代、有限记忆二阶近似、仅 primal warm start
及尺度/非线性病态是可信候选机制，但现有数据不能确定哪一项导致反复不收敛；未发现一条可据此宣称的确定 solver bug。
任务为离线执行，耗时超过控制周期不改变本次物理验收，也不是保持速度的直接时间延迟。

### 降刚度末次失败的影响

0.34 s 求解虽保留一个小违反计划，但 raw status 为 Error_In_Step_Computation，
按原策略判为 unusable，**没有施加该计划**，只沿用上一六路张力。
其保存的未执行首输入约 `[6.663,8.00000008,4.539,2.515,1.813,1.621] N`，与实际保持输入明显不同；
不能拿其预测对比实际终点称同输入误差，或将未执行的 8 N 输入称实际饱和。
终点 0.052030 m/s 混合了结构、此前闭环状态和最后 hold-last 响应，不能用它隔离刚度效应。
原 solver_error_count=0 只是没有 Python solver exception，不表示 IPOPT 没有失败。

因此当前竞争解释为：**软目标及终端时序权衡、迭代受限的次优控制、状态表示/动力学与时间离散预测偏差、
以及降刚度最后的 fallback**。增刚最后命令跳变与末端反弹同时出现，支持检查终端控制；尚不足以证明跳变是唯一原因。
两次位置通过反驳本例“长度必然不足”的解释，不构成整个设计域的可行性证书。
