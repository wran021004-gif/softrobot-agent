\section{Architecture Comparison Protocol}
\label{app:abc-protocol}
\subsection{Interfaces}
\paragraph{LLM-only}
The agent generates and revises structures and controls using the frozen task and physical-evaluation feedback. It can set control inputs, execute a candidate, and read its task evaluation.
\paragraph{Direct Mathematical Tools}
This interface adds Jacobian, equilibrium/KKT, finite-difference, and supported optimization operations. The agent constructs the mathematical question and tool request directly.
\paragraph{Full framework}
The full interface compiles research intents into task-conditioned problems, routes numerical execution, and returns linked evidence for refinement.

\subsection{Evaluation}
The comparison comprises eleven tasks and three research interfaces, giving 33 task--method configurations. All methods use GPT-5.6 Sol, the same frozen task contracts, admissible design spaces, structure-generation capabilities, physical models, and independent evaluators. Each configuration is evaluated over ten runs, each limited to 30 mathematical operations, 30 physical evaluations, and 60 agent requests.

A task is completed if at least one run selects a candidate satisfying every required condition. The three-interface comparison reports task-level completion. Resource consumption is reported for the Knowledge/Skill ablation and full-framework backbone comparison: for each resource metric, the task value is the minimum among passing runs, or the mean across all ten runs if none passes; portfolio totals sum these task-level values. Mathematical operations count analysis or optimization calls, physical evaluations count independent task-evaluation calls, and agent requests and token consumption follow the recorded model usage. Table~\ref{tab:abc-comparison} reports task-level feasibility discovery, and Appendix~\ref{app:task-portfolio} defines the physical quantities used for acceptance.


\subsection{Recorded Model and Interface Configuration}
The archived baseline configuration and full-framework runtime identify the model as \texttt{gpt-5.6-sol} and configure medium reasoning. The parameter-tradeoff context replay uses the same model identifier with reasoning set to \texttt{none}; its fixed system prompt requests one next research decision and permits \texttt{research\_plan}, \texttt{research\_recall}, and \texttt{evidence\_read} within four provider requests.

{\raggedright The archived baseline command interface exposes \texttt{generate}, \texttt{evaluate}, and \texttt{finish} to both methods. Direct Mathematical Tools additionally exposes \texttt{math} with \texttt{jacobian}, \texttt{mechanics}, \texttt{finite\_difference}, \texttt{equilibrium}, and \texttt{kkt} operations. Its direct-optimization records additionally use nonlinear least squares for configuration fitting and bounded SLSQP for tendon-force allocation. The archived full-framework configuration permits structure generation, control initialization, physical replay, diagnosis, selection, and stopping, together with candidate-bound mechanism analysis, condition-wise control optimization, and comparison of saved control-adapted responses. Task configurations specify the enabled subset.\par}
