# 二、组织六类通用能力

在现有工具目录、能力描述和解析器上完善，不另造一套重复框架：

1. 设计表达与编译：设计参数、约束、机器人中间表示、仿真模型生成。
2. 数学建模与分析：几何、静态、动态、导数、辨识和敏感性。
3. 设计与控制生成：候选生成、参数搜索、轨迹和控制方案。
4. 仿真与实验执行：后端启动、输入施加、运行、预算与恢复。
5. 评价、诊断与观察：指标、约束、模型比较、曲线和动画。
6. 代码与能力管理：能力查询、输入示例、实现入口、版本和验证证据。

预算、权限、状态、证据和来源追溯作为公共服务。

每个工具至少说明：

* 能解决什么问题。
* 输入输出、单位、坐标系与时间语义。
* 使用假设、不支持的情况。
* 实际实现入口和依赖。
* 已实现、已验证、已标定的独立状态。
* 后端调用成本和已有证据。

MATLAB、MuJoCo 是执行后端，不是任务专属工具分类。新增任务应尽量复用同类能力。

禁止只有名称和空函数的能力；不适用和未实现必须可查询。避免“任务失败就返回工具不支持”等混淆。

# 三、把动态可视化做成主要交付

提供一个简单、统一的观察入口。可以使用现有原生窗口或轻量本地界面，不要求复杂前端。

至少支持：

* 打开一个已有运行，查看MuJoCo机器人实际运动。
* 播放MATLAB成功求解的动态轨迹及其中心线。
* 同一设计下固定指令和反馈控制的并排或叠加比较。
* 播放、暂停、逐帧、慢放、时间拖动和视角调整。
* 同步显示末端误差、末端坐标、腱长目标/实际值和腱力。
* 显示目标、坐标系、时间、模型名称、设计和控制方式。
* 导出截图及至少一种可播放的视频或动画格式。

优先读取已保存的数据。观看、换视角、画图、导出视频不得触发新仿真。

统一数据读取接口，应覆盖：

* 时间戳和状态。
* 机器人形状或可重建形状的状态。
* 控制输入、腱长、力。
* 任务目标和事件。
* 模型版本、结果状态和来源。

注意现有位置记录在积分后，部分力/接触记录来自施力阶段。保留原始时间语义，不把不同阶段的数据伪装成同时采样。

加载旧数据时：

* 缺失字段明确显示不可用。
* 从保存状态重建几何可以接受，不重新推进动力学。
* 重新计算的显示量必须与原始记录区分。
* 原记录只有接触数量时，不虚构接触位置或原始接触力。
* 新运行可按需求补充接触位置、对象和力等记录；验证记录功能不会改变仿真结果。

MATLAB和MuJoCo只有在输入、时间、坐标及比较对象相容时，才能输出定量差异。

几何插值动画必须标记为几何演示。静态平衡形状不能冒充动态轨迹。失败的动态计算不能用插值补出完整预测。

优先复用第三轮成功的静置、衰减和受力响应数据制作MATLAB动态展示。主任务预测失败时，界面显示失败原因和已有证据。

# 四、审计模型限制，并提高失败的可解释性

当前简化模型用一个总弯曲角描述平面运动，忽略接触及其他形变。代码设有2.8和3.2弧度相关边界。

本轮必须整理一张限制来源表，区分：

* 任务成功条件。
* 用户授权的设计包络。
* 有依据的物理或几何限制。
* 模型结构假设。
* 实现者设置的数值保护。
* 求解时间、迭代和实验预算。

对每个限制记录值、单位、来源、理由，以及触发后意味着什么。

没有推导或实测依据的实现阈值，明确写为“实现选择，尚未证明是物理有效范围”。不要补写不存在的用户批准或物理结论。

优先读取三次历史失败的原始记录。记录不足时说明不足；可以在本轮验证预算内对必要的代表输入进行一次带诊断的复查，不重跑主设计实验。

改进新求解结果的诊断信息：

* 触发的限制和实际值。
* 触发时间、状态、速度和输入。
* 求解器内部试算点还是已接受的状态。
* 最后有效样本及其来源。
* 数值错误、程序保护中止、条件不适用的区别。

部分轨迹只用于诊断，不得当成完整成功预测。无法恢复的历史数据不能伪造。

本轮允许在独立分析版本中修复实现错误、改进边界报告，必要时探索更合适的简化表示。保留旧版本；不得通过单纯删断言、裁剪轨迹或调小输入来宣称模型修复成功。

不要因为三次边界失败就预先认定必须更换某一种高级模型。先区分输入语义、坐标、受力、初态、形变自由度和接触条件。

至少建立一组真正可解释的、相同输入条件下的MATLAB与MuJoCo动态对照。可以采用不含接触的小型独立验证场景，明确两边自由度和参数映射。若存在降阶近似，报告近似误差，不宣称严格等价。

这组对照是工具验证，不替换冻结主任务，也不是实际材料标定。无需为此建设完整Cosserat或有限元平台。

# 五、准备三个任务族的统一接口

准备：

1. 自由空间到达。
2. 有障碍的到达。
3. 扰动条件下的末端稳定。

准备的是任务定义、实例生成和评价接口，不是三套预先写死的解题流程。

每类任务表达：

* 环境和初始条件。
* 目标、约束和观察量。
* 允许变化的实例参数及随机种子。
* 评价时段、指标和成功条件。
* 可调用的通用工具和仍缺失的能力。
* 开发实例与独立评估实例的划分方式。

复用已有到达任务和避障开发场景。末端稳定任务明确目标在哪个坐标系，以及扰动是作用在基座还是外力，不能混用两种物理过程却共用同一个名称。

新参数和成功标准若没有既有批准，先以明确的开发任务版本落地并给出依据；不自动修改正式基准或伪造批准。无需因此停止其他已授权开发。

三类任务均应有可执行的开发示例和正常评价结果，不要求机器人全部成功。采用现有控制器完成接口验证即可，不为每个任务人工设计一套专属求解算法。
