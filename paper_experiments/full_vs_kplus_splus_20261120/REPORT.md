# 历史 FULL 与当前 K+S+：11 项研究的量化对照

比较对象仅为两组：历史 FULL（`15d466705` 的论文归档）与当前 K+S+（`ed1419b` 的 11 个正式单元）。用途是描述两次完成研究所记录的行动和成本。两组最终所选结果均为 11/11 required-task PASS，每项最终归一化违反量均为 0。

数学计费评价 **322→388（1.20×）**，物理启动 **93→267（2.87×）**，保存的 Core 请求 **895→3,050（3.41×）**。已记录积分步数 **28,974,100→30,774,833（1.062×）**；启动次数的增长大于已记录积分量的增长。积分量含数学内部 rollout 和独立物理执行，覆盖不完整。

当前组已记录 input **284,928,092**、output **1,091,143**，合计 **286,019,235 token**；input 已含 **278,907,648 cached token**。历史没有原始 token 用量，换算估计为 **105,134,989 token**，假设范围 **52,567,493–210,269,978**。历史估计是按当前实现换算的等效工作量，不能据此声称历史真实消耗或真实费用降低/增加了某一比例。

## 数学操作与物理操作怎样统计

数学保留三个层级：数学分析入口记录、原生 computed/complete 结果、预算计费评价。历史分析执行入口 51 条，当前数学接口请求 145 条；当前包含被拒绝/失败的接口请求，历史入口多为已派发执行，二者不直接当作相同的“尝试次数”。历史已保存 computed 分析结果 51 条，当前明确 complete 的数学证据 93 条。初态构造请求另为 4→13，初态资格检查请求为 3→10，不与计费评价相加。旧 `research.math` 是调度层，未再与 `research.candidate_analysis` 重复累计。

实际调用过的数学操作及状态见 [MATH_METHOD_COUNTS.csv](MATH_METHOD_COUNTS.csv)，每次调用的 request/artifact/source 见 [MATH_METHOD_EVIDENCE.csv](MATH_METHOD_EVIDENCE.csv)。包括原生非线性任务能力、直接控制、机制结构分析、平衡、线性化和短时输入响应等；失败和 not_applicable 也保留。这里的操作名不自动代表某种结构敏感性分析。

物理启动采用两组原账本的实际记录，保留每项任务被动载荷展开、失败执行和控制器生命周期启动的原有计数。另存物理结果记录、已记录积分步数及缺口；不把数学内部 rollout 作为独立物理验收次数。Core 请求包括证据读取、决策记录、调度、失败请求及数值行动，适合作为研究交互工作量。两版接口会把一个研究行动拆成不同数量的请求。

## 缺失 token 的估计

逐任务、分别估计 input 和 output：`历史 token 估计 = 历史保存的 Core 请求数 × 当前同任务已记录 token / 当前 Core 请求数`，分别四舍五入为整数后相加。缓存 token 用同样规则估计，仅为 input 的子集；reasoning 已包含在 output，不再相加。每项历史中心估计的 0.5–2 倍作为假设范围，各项上下界相加得到总范围。这不是抽样置信区间，也不恢复缺失的供应商账单。当前中断未记录用量没有再任意加一个百分比，保留 recorded lower bound。

不同实现的请求粒度和上下文长度会影响换算，PHS 尤其明显：历史物理载荷会在单个调用中展开，当前大量分页读取会增加请求数。因此 token 估计适合预算或等效工作量讨论；真实 token 成本仍 unavailable。没有指定模型价格、缓存计费方式和实际供应商请求数，所以不换算货币费用。

数值时间另保留原记录：历史累计数值/计费时间约 **22,473.46 s**，当前 **85,547.29 s**。当前含保守退出计费，历史若干版本使用不同数值时间口径；它们不是统一测得的 CPU 时间，不作为核心成本倍率。未估计 CPU。

## 数据范围与证据入口
