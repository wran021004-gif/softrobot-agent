# Reach/Hold Native Study：监督与原因审查

## 结论和来源

Study `reach-hold-native-autonomous-r2-20261027` 在代码 `455ec55347ce6ab05cfbf71ad439044e9db77aca` 冻结，以原始 Reach/Hold 任务、空候选池、独立 Store 和 Provider 会话运行。Agent 给出并成功提交 STOP；没有 SELECT，也没有完整任务评价。原始证据、收据和停止决定见同目录的不可变归档、disposition 与 calls。以下明确区分 Agent 原话、科学工具计算、Reporter 和 Codex 审计；监督判断没有注入 Agent。

## Agent 第一项结构决策

Agent 自主选择三段、五腱、distributed_consecutive、圆截面，搜索长度与截面半径，最多三候选和三分析单位，采用零张力、四个控制结点、全 0.35 s 窗口、最多 51 回调及 6 轮 response。其原始假设是长度决定可达弦长，弯曲刚度和腱力矩可能限制到达和保持；它预期较小截面及更接近目标距离的长度降低 J，并称几乎相同或无改善的结果会削弱假设。原始计划见结果归档中 `original_research_plan` 和搜索请求。Codex 审计：这是基于公开工程默认值的启发式推测，不是已验证因果；Agent 把 J 描述为“米”并与 0.01 m 比较有单位错误，J 是无量纲 signed normalized violation。

## 工具结果与路线

首次搜索构造三结构，实际消耗 3 个数学分析单位。三次 Native rollout 分别完成 327、325、331 物理步后因 `FactorizeHessian: rank-deficient sparse Hessian` 终止，未完成一个可计分回调，初始 J、最好 J 和优化后的控制都不存在。修复后的起步投影正确标记 `completed_unresolved` 并释放后续路线。Agent 随后选择独立回放、进一步 Native 分析、尝试生成新结构、修改控制初始化及再次回放；其具体输入、假设与反馈均保存在各原始请求与报告。全部五个 Native 分析未完整，累计 5 次模型构建、5 次部分 rollout、1639 次已完成物理步、1644 次尝试步和 175 次 forward evaluations；其余 Native 成本细目见分析收据。四次独立回放均未完整，已确认完成的步数为 331、321、366、325；没有终点误差、保持误差或保持速度。没有最佳可排序 Native J，也没有最佳完整物理结果。

Agent 对四种控制输入的比较包含零张力、较大阶跃、平滑上升以及恒定 0.2 N；这些尝试均未完成。它正确指出约束未被测量、无通过、不能据此证明全局不可行。但它进一步宣称任意新控制无法帮助、结构生成不可能以及未来合法行动无法产生指标，这些比现有证据更强，不能由局部数值失败或错误请求证明。首次 STOP 所用 `engineering_unavailability_of_execution_with_no_task_level_conclusion` 推断被证据门禁拒绝；Agent 随后以 `empirical_search` 提交 STOP，系统接受。已接受 STOP 中仍含上述过度推断，应按原始 Agent 表述保留，而非作为监督结论。

## 原因审查

1. **MuJoCo 失败：原因未确定。** 五个 Native 记录和四个独立物理回放的直接异常均为稀疏 Hessian 秩亏。四次独立回放在约 0.1605–0.183 s 的 `playback.step` 失败；失败调用前记录 ncon=0、nefc=0，时间步 0.0005 s。记录缺少失败瞬间状态和求解器内部进度，因此调用前无接触不能证明失败瞬间无接触，现有证据无法分辨接触、数值条件、模型结构、积分器或加载的作用。不同输入和两种结构出现同类错误是相关观察，不是对任一原因的因果证明。
2. **生成接口：真实反馈缺陷加 Agent 误判。** 首次 V2 请求把段索引写成 `segment_0` 等字符串，而请求模型要求整数键；错误摘要却先展示 V1 联合类型分支，误导 Agent 改用 V1，后者被 V2 FamilyBuild 拒绝。另一请求的截面数量与冻结原型站点数不一致，得到 `EXACT_SECTION_STATIONS_REQUIRED`；Agent 随后把 `s` 直接放在 Section 对象中，Pydantic 正确拒绝。`Section` 无 `s`；生成器按顺序用 Section 对象替换原型站点的截面，站点位置由原型保留，数量必须匹配。静态契约核查证实 Plan V2 和 FamilyBuildV2 使用相同 GenerationRequestV2；仅去掉错误 `s` 字段后，该计划可通过 Plan 语法验证，但原型首段和后续段的站点数量不同，仍须按各自数量构造。这里未执行新结构或科学试验。Agent 宣称两版本不可同时满足没有证据支持。工具应改善联合分支错误投影和站点数量说明。
3. **初次 Study 门禁：已修复。** 已结算但不完整的 Native rollout 有物理步数却没有完成回调数，旧投影因只检查回调而错误地把有限搜索视为未完成。修复读取已拥有收据中的实际物理步数，并保留结果完成和未准入的检查；当前 Study 的真实首次搜索验证了释放状态。前一 Study 保留独立封存和全部费用。
4. **Provider 中断：远端结果未知。** 第 33 次请求连接被远端断开且无本地响应；不能确定服务端是否产生了结果。经原有恢复检查核实原进程退出、工具调用已配对、无其他未结算工作。用户明确授权仅将本地响应记为丢失、保留原请求费用并以新计费请求恢复；远端结果仍未知，未重跑已完成科学实验。

## Knowledge、Reporter 与费用

Agent 两次主动检索历史经验（Reach 和失败类型查询），均无匹配；没有实际读取历史经验，也没有证据显示其改变了研究判断。Reporter 共 3 次 Provider 请求；系统记录 20 条 research_report（含确定性报告）。报告解释不能替代独立物理执行。最终 34 次 Provider 请求（31 次主会话、3 次 Reporter，其中 1 次响应丢失）、33 次公共操作、5 个数学分析单位、4 次独立物理启动；剩余分别 30、87、7、2（独立回放上限还剩 1）。已收到 33 次响应所报告的 token：输入 3,213,723、输出 143,419、合计 3,357,142；丢失响应的实际 token 和费用未知，不能当零。Store 记载累计 numerical_s 13.5830695；账本 wall_s 为 1012.3637388，导出时 elapsed_s 约 1419.15。无 PPO 或 NMPC 启动。
